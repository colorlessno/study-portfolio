# security10 .env / secrets管理 要件定義

## 1. 目的

秘密情報をソースコードやGit履歴へ入れない基本を学ぶ。

## 2. 学習対象

- `.env`
- `.env.example`
- `.gitignore`
- secret leakage
- environment variable

## 3. 作成する成果物

- `.env.example`
- `.gitignore`例
- 秘密情報チェックリスト
- 誤コミット防止メモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | `.env.example` に必要項目だけ記載できる |
| FR-02 | `.env` をGit管理対象外にできる |
| FR-03 | 秘密情報を環境変数から読む例を作れる |
| FR-04 | 誤コミット時の初動を整理できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 実秘密情報を含めない |
| NFR-02 | サンプル値は明らかなダミーにする |
| NFR-03 | Git履歴に入った場合は削除だけでは不十分と説明する |

## 6. 対象外

- Secret Manager本格運用
- 鍵ローテーション自動化
- CI/CD secret設定

## 7. 受入条件

- `.env` と `.env.example` の違いを説明できる
- 秘密情報をGitに入れない理由を説明できる
- 漏洩時は無効化・再発行が必要と説明できる

## 8. 学習観点

- 秘密情報は設定でありコードではない
- `.gitignore` は事故防止の最低限
- 一度漏れたsecretは交換する
