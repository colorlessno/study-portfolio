# security19 Tool実行前承認 要件定義

## 1. 目的

AIがファイル操作や外部操作を行う前に、人間承認を挟む設計を学ぶ。

## 2. 学習対象

- tool approval
- allowlist
- destructive action
- human-in-the-loop
- audit log

## 3. 作成する成果物

- Tool実行疑似サンプル
- 承認待ちキュー
- 許可・拒否フロー
- 監査ログ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | AIが提案した操作を承認待ちにできる |
| FR-02 | 許可された操作だけ実行済みにできる |
| FR-03 | 拒否理由を記録できる |
| FR-04 | 危険操作をallowlist外として拒否できる |
| FR-05 | 操作履歴を監査ログに残せる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 実破壊操作は行わない |
| NFR-02 | 学習用の疑似操作に限定する |
| NFR-03 | 承認者と実行者を区別する |

## 6. 対象外

- 実ファイル削除
- 外部サービス実操作
- 複雑なワークフローエンジン

## 7. 受入条件

- 危険操作前に承認が必要な理由を説明できる
- allowlistと監査ログの役割を説明できる
- AI判断だけで実行しない設計を確認できる

## 8. 学習観点

- AIエージェントには操作範囲制限が必要
- 人間承認は安全装置である
- 何を実行しようとしたか記録する
