# db03 正規化とERモデリング

非正規な注文表から、繰り返し項目と更新時の問題を見つけ、正規化したERモデルへ段階的に変換します。

## 到達目標

- 挿入・更新・削除時に起きる不整合を具体例で説明できる。
- 1NF、2NF、3NFで何を分離したかを説明できる。
- 正規化と、読み取り都合の非正規化を目的で使い分けられる。

## 始める前の問い

- 注文1件に商品が複数あるとき、1行へ押し込むと何が困るか。
- 顧客住所の変更で過去の配送先も変えてよいか。
- 商品名を注文時点の記録として残すなら、どこに持つか。

## 15分で再開

1. 非正規な注文表から、同じ意味が繰り返されている列を3つ探す。
2. 更新・挿入・削除の異常を1つずつ書く。
3. ERモデルと見比べ、どのテーブルがどの異常を防ぐか線で対応させる。

## 手を動かす課題

非正規表へ「配送先」と「割引」を追加すると仮定し、どのエンティティに属するか決めます。その後、レポート向けに非正規化するなら何を複製し、どれを正本にするかを書きます。

## 完了条件

正規化後の各テーブルの主キーと関係を説明し、非正規化の利点と同期リスクを1つずつ説明できれば完了です。このテーマではDockerを使いません。
