# web37 業務フォーム完全版

依存パッケージを使わない静的 HTML / JavaScript で、入力検証、項目別エラー、送信中表示、二重送信防止、成功表示を観察する。業務フォームに必要な状態を整理し、現実装に不足している確認・失敗状態を発展課題として実装する。

## このテーマで身につけること

- 入力値、検証エラー、送信状態、送信結果を分けて考える
- 利用者が修正できる項目別エラーを設計する
- 非同期処理中に送信ボタンを無効化する理由を説明する
- 要件、設計、実装の差を発見し、次の改造項目へ落とし込む

## 10分で再開する

Docker で同じ HTTP origin を再現する。

```powershell
cd category/StudyWeb\src\frontend\static\studyweb\systems\web37_business_form_complete
docker build -t studyweb-web37 .
docker run --rm -p 3037:80 studyweb-web37
```

`http://localhost:3037/app/` を開く。終了は `Ctrl+C`。

簡単な確認なら `app/index.html` を直接開いても動作する。コードの構文だけを確認する場合は次を使う。

```powershell
node --check app/src/main.js
```

## 最初に試す順番

1. すべて空欄で `確認` を押し、顧客名とメールのエラーを確認する
2. 顧客名を入力し、メールに `example` を入れて形式エラーを確認する
3. 備考に201文字を入れ、文字数エラーを確認する
4. 正常値で送信し、約400ミリ秒の `送信中...` とボタン無効化を見る
5. 成功表示に顧客名とメールが反映されることを確認する

検証条件は [Validation Rules](docs/validation_rules.md)、状態の整理は [Form State](docs/form_state.md) を参照する。

## コードを読む順番

1. `app/index.html` で label、input、エラー表示用 span、submit button の関係を見る
2. `validate` で3項目のルールと `errors` オブジェクトの作り方を見る
3. `form.onsubmit` 冒頭の `preventDefault` と、前回エラーの消去を確認する
4. エラーがある場合の早期 `return` を追う
5. `submit.disabled`、待機処理、成功表示、再有効化の順番を追う

## 現実装で確認できる状態

| 状態 | 確認方法 | 現在の表示 |
|---|---|---|
| input | 初期表示・入力中 | フォーム |
| validation error | 不正値で送信 | 項目別メッセージ |
| submitting | 正常値で送信 | `送信中...`、ボタン無効 |
| success | 待機完了 | 顧客名・メールを表示 |

要件にある確認ステップ、送信失敗、フォーム全体エラー、エラー項目へのフォーカス移動は未実装である。「完全版」という名称に対して実装が不足しているため、ここを発展課題として扱う。

## 観察ポイント

- 検証に失敗した場合は非同期処理へ進まず、入力値はそのまま残る
- メール検証は学習用の単純な正規表現であり、完全なメール仕様検証ではない
- 備考は任意だが、入力した場合は200文字以内に制限される
- ボタンを無効化することで、送信待機中の同じ操作を画面から繰り返しにくくしている
- 現在は成功処理の後で必ずボタンを戻すが、本物の通信では `try / catch / finally` を検討する

## 壊して確かめる

- 待機時間を3秒へ変え、送信中にボタンを再度押せないことを確認する
- `submit.disabled = true` を一時的に外し、連続操作が起こす問題を説明する
- 最初のエラー項目へ `focus()` する処理を追加し、キーボード操作を改善する
- 入力画面と確認画面を分け、確認後にだけ送信処理へ進むよう改造する
- 特定のメール値で失敗させ、項目エラーとフォーム全体エラーを分けて表示する

## 自分の言葉で説明する

- field error と form error は何が違うか
- 送信中にボタンを無効化しても、サーバー側の二重登録対策が別に必要なのはなぜか
- 入力値を失わずにエラーを表示することが重要なのはなぜか
- 現実装と要件定義の差を、実装済み・未実装に分けて説明できるか

## 完了条件

- 3種類の検証エラーと正常送信を再現した
- input、validation error、submitting、success の遷移を説明できる
- 二重送信防止の動作を確認した
- 未実装の確認・失敗状態から1つ以上を自分で追加した
