# base04 テスト成立条件チェック 要件定義

## 1. 目的

テストを実施する前に、環境、データ、手順、権限、外部連携、判定基準がそろっているか確認できるようにする。

## 2. 学習対象

- テスト成立条件の整理
- テスト環境と本番環境の違い
- テストデータの準備条件
- 期待結果と判定基準
- 実施不能条件と代替案

## 3. 作成する成果物

- テスト成立条件チェックリスト
- テスト環境確認表
- テストデータ確認表
- 判定基準一覧
- 実施不能条件と代替案メモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | テスト対象機能を記録できる |
| FR-02 | 必要な環境、アカウント、権限を記録できる |
| FR-03 | 必要なテストデータと作成手順を記録できる |
| FR-04 | 実施手順、期待結果、判定基準を記録できる |
| FR-05 | 未充足条件と代替確認方法を記録できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 手作業テストと自動テストの両方に使える |
| NFR-02 | 実施不能な理由を責任追及ではなく条件不足として表現する |
| NFR-03 | 後続の Playwright / API test / CI に接続できる |

## 6. 対象外

- 詳細なテストケース全量作成
- 自動テスト実装
- テスト管理ツール導入

## 7. 受入条件

- テストに必要な環境、データ、権限、手順、判定基準が確認できる
- 未充足条件と代替案が記録されている
- テストできない理由が構造化されている
- 後続の自動テスト設計に使える

## 8. 学習観点

- テストは手順だけでは成立しない
- 環境やデータ不足は明示する
- 判定基準がないテストは確認にならない
