# security05 401 / 403 / 404 の使い分け 要件定義

## 1. 目的

未認証、権限不足、存在しないまたは存在を隠したい場合のHTTP応答を使い分ける。

## 2. 学習対象

- 401 Unauthorized
- 403 Forbidden
- 404 Not Found
- 存在秘匿
- API error body

## 3. 作成する成果物

- 401/403/404確認API
- 判定表
- curl確認手順
- フロント表示例

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 未ログイン時に401を返せる |
| FR-02 | 権限不足時に403を返せる |
| FR-03 | 存在しないIDで404を返せる |
| FR-04 | 存在秘匿のため404を返す方針を確認できる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | エラーbodyを共通形式にする |
| NFR-02 | 内部情報を返さない |
| NFR-03 | 利用者向け表示と開発者向けログを分ける |

## 6. 対象外

- 詳細な監査ログ
- 多言語エラー
- OpenAPI生成

## 7. 受入条件

- 401/403/404の違いを説明できる
- APIとフロント表示を対応づけられる
- 存在秘匿の考え方を説明できる

## 8. 学習観点

- 401はログインが必要
- 403はログイン済みだが権限不足
- 404は存在しない、または見せない方針で使うことがある
