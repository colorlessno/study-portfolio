# base02 情報不足時の暫定成果物 要件定義

## 1. 目的

情報が不足している状態でも、作業を止めるだけでなく、書ける範囲、書けない範囲、未確定事項、確認先を分けた暫定成果物を作れるようにする。

## 2. 学習対象

- 暫定成果物の作り方
- 前提、仮定、未確定事項、確認事項の分離
- 成果物の限界を明記する方法
- 情報源と根拠の残し方
- AI が補完した内容を事実と混同しない確認方法

## 3. 作成する成果物

- 暫定成果物テンプレート
- 前提・仮定一覧
- 書ける範囲 / 書けない範囲一覧
- 未確定事項一覧
- 成果物限界メモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | 情報不足の入力ケースを用意できる |
| FR-02 | 書ける範囲と書けない範囲を分けて記録できる |
| FR-03 | 前提、仮定、未確定事項を別項目として記録できる |
| FR-04 | 情報源、根拠、更新日を記録できる |
| FR-05 | 成果物の限界とレビュー観点を添えられる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | Markdown だけで作成・レビューできる |
| NFR-02 | 不明点を断定表現にしない |
| NFR-03 | 後続の要件定義、設計、見積もりで再利用できる |

## 6. 対象外

- 情報不足を解消した完成仕様書の作成
- 関係者への実際の問い合わせ送信
- 実装

## 7. 受入条件

- 書ける範囲と書けない範囲が明確に分かれている
- 未確定事項に確認先、確認内容、期限がある
- 成果物の限界が明記されている
- AI が推測した内容が仮定として扱われている

## 8. 学習観点

- 情報不足でも作れる成果物はある
- 不明点を埋めることと、不明点を管理することは違う
- 暫定成果物には限界と前提を添える
