# security04 owner_id / tenant_id 認可 要件定義

## 1. 目的

自分のデータだけ参照・更新できる認可を学ぶ。

## 2. 学習対象

- owner_id
- tenant_id
- horizontal privilege escalation
- データ参照権限
- 404による存在秘匿

## 3. 作成する成果物

- owner_id認可サンプル
- tenant_id認可サンプル
- 他人データアクセス拒否例
- 404/403使い分けメモ

## 4. 機能要件

| ID | 要件 |
|---|---|
| FR-01 | データにowner_idを持たせられる |
| FR-02 | ログインユーザーのデータだけ取得できる |
| FR-03 | 他人のデータアクセスを拒否できる |
| FR-04 | tenant_idで組織境界を分けられる |
| FR-05 | 403/404の方針を選べる |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | IDを推測されても他人データを返さない |
| NFR-02 | 一覧と詳細の両方で認可チェックする |
| NFR-03 | 認可漏れをテスト観点に含める |

## 6. 対象外

- 複雑な組織階層
- row level security本格実装
- マルチテナント課金

## 7. 受入条件

- 他人のIDを指定してもデータを取得できない
- 一覧APIでも他人データが混ざらない
- owner_id / tenant_id の目的を説明できる

## 8. 学習観点

- ログイン済みでも全データを見てよいわけではない
- ID推測は実際に起きる
- 認可は各APIで確認する
